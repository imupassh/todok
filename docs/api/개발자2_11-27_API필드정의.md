## 1. 공통 규약 (11/27 공통 규격 확정 가정)

| 항목 | 규칙 |
| --- | --- |
| 응답 봉투 | 성공 `{ "data": <body> }` · 실패 `{ "error": { code, message, details? } }`. YAML 스키마는 봉투 안 `data` 본문만 표기 |
| 식별자 | 외부 `id` = `public_id`(UUID). 내부 순번 PK 미노출(D-2 보안) |
| 목록 | 커서 페이지네이션: `?cursor=&limit=`(기본 20·최대 50), 응답 `meta.nextCursor` |
| 시간 | ISO-8601 UTC(TIMESTAMPTZ), 앱이 상대시간 변환 |
| 비교 수치 | 재생·반응·편지 수 미노출(C-09). 반응은 코드만, 개수 아님 |
| 음성 | 서버 미경유: 업로드=S3 서명 URL PUT→완료 API, 재생=짧은 서명 URL 스트리밍 |
| 인증 | 17개 전부 로그인 필수(S-01), `Authorization: Bearer <JWT>`. 만료 시 401 AUTH_EXPIRED |

## 5. 설계 결정 메모 (리뷰 포인트)

- **북마크 교체 흐름**: `PUT /letters/{id}/bookmark`가 30개 가득이면 409 + `oldestBookmark`. 앱이 팝업 동의를 받으면 `{"replaceOldest": true}`로 재요청 → 가장 오래된 1개 삭제 후 저장(트랜잭션).
- **open vs stream-url**: 최초 열람은 `POST /open`(24h 타이머 시작 + URL), 이후 재생은 `GET /stream-url`(타이머 영향 없음). 북마크 편지는 24h 지나도 `stream-url` 가능.
- **upload → create 2단계**: `upload-url`에서 한도·제재·마감 선검증(서명 URL 아끼기), `POST /letters`에서 우표 필수·마감 재검증(L-04 `submitted_at` 기록).
- **reaction/open 응답 최소화**: 반응 등록은 204, 개수 미반환(C-09).
- **공통 응답 봉투·페이지네이션 방식**은 11/27 공통 규격 회의 확정 가정 — 확정 시 YAML 전역만 조정.
